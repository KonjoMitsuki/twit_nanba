# データ分析プロトタイプ

既存のカレンダーとは別の `/analytics` に、Notion風の個人用分析スペースを追加します。FastAPI、SQLite、素のHTML/CSS/JavaScriptを使用し、グラフは外部CDNに依存しないSVGで描画します。

## まず画面を試す

```bash
pip install -r requirements.txt
APP_DB_PATH=./app.db PYTHONPATH=. python -m uvicorn api.main:app --host 127.0.0.1 --port 8000
```

`http://127.0.0.1:8000/analytics?demo=1` を開きます。デモは生成した作品・計測・フォロワー履歴のみを使用し、アプリDB・Notion・Xからデータを取得しません。作品テーブル、キャラクター別の伸び、ダッシュボードを操作できます。利用者A/Bの切り替えで設定の分離も確認できます。

デモの設定は利用者ごとにブラウザーのlocalStorageへ保存します。デモのキャラ編集は同じブラウザーのA/Bで共有します。

## ログインなしの利用者切り替え

実データは `http://127.0.0.1:8000/analytics` からそのまま利用できます。Googleアカウント・OAuth設定・許可メール・セッション秘密鍵は不要です。

サイドバーの利用者名で切り替えます。最初は「利用者A」「利用者B」を用意し、名前の変更と利用者の追加ができます。選択は端末に記憶し、ビュー設定は利用者ID別にSQLiteへ保存します。同じ利用者名を別端末で選ぶと同じビューを利用できます。名前を変えてもIDと保存済みビューは維持します。

**利用者名は設定を分けるためのもので、本人確認やアクセス制限には使いません。誰でも別の利用者を選び、その設定を表示・編集できます。** 作品データとキャラ編集は全利用者で共通です。

既存のカレンダー・作品取得・巡回操作にもログインは不要です。異なるサイトからのブラウザー経由の変更リクエストは拒否します。旧Google設定が環境変数に残っていても使用しません。以前のGoogle ID名義のビューを含め、既存レコードは削除しません。自動で新しい利用者に付け替える処理も行いません。

## ビューとダッシュボード

- テーブル、折れ線、円、箱ひげ図、ヒストグラムを追加できます。
- 作品・計測ログのテーブルは投稿写真のサムネイルを先頭に表示します。写真から作品詳細を開け、複数画像の投稿は枚数を表示します。画像なし・読み込み失敗は文字で表示します。「軸・集計」の「投稿写真を表示」で非表示にもでき、設定はビューに保存します。既存ビューにも標準で写真を表示します。
- 単独表示ではパネルをタブで切り替え、ダッシュボードでは同時に並べます。
- パネルは上下ボタンで並べ替えられます。ドラッグ操作は必須ではありません。
- ビュー名、各パネルのデータ・軸・系列・計算・見た目を個人ごとに自動保存します。
- ビューの作成・複製・削除ができます。ビュー削除で作品や計測は削除されません。
- 保存した条件を開くたび、現在のデータを再集計します。「直近30日」などの相対期間も保存できます。
- 約650msの入力待ち後に保存します。失敗時は未保存と表示し、再接続または「更新」で再試行します。
- 未保存の下書きは利用者ごとにブラウザーにも保持します。同じビューを別タブで変更した場合はrevisionを検証し、自動で上書きせず、変更を別ビューに保存するか保存済み設定を使うかを選べます。
- PC・スマホとも同じ設定項目を編集できます。スマホの設定は全画面のダイアログで表示します。

## データの粒度と時間

| データ種類 | 1行の意味 | 期間の基準 |
|---|---|---|
| 作品ごと | 1作品の指定した計測ステージ | 投稿日（JST） |
| 計測ログ | 1作品の1計測 | 投稿日（JST） |
| フォロワー履歴 | アカウント全体の1計測 | 計測日（JST） |

作品比較の時点は `config.SCHEDULE_STAGES` から選択します。24hが指定されている場合、24hの計測がない作品に1hや最新値を代入しません。テーブルでは未計測と表示し、グラフでは除外件数を表示します。元データの数値をゼロで補ったり書き換えたりしません。

フォロワー履歴は `account_metrics` を使用します。作品のスナップショットに含まれるフォロワー数を、特定のキャラによる獲得数として帰属させません。

開始日・終了日は両端を含みます。終了日の指定がなければJSTの当日を使用します。明示した開始日を優先し、なければ「直近の日数」を使用します。開始日も日数も指定しない場合は全期間です。

前期間比較では同じ長さの直前の期間を別系列として表示します。日付軸では前期間の日付を現在の期間へシフトして重ねます。元の保存日時は変更しません。前期間比較は折れ線・箱ひげ図・ヒストグラムに対応します。

## 計算とグラフ設定

横軸・分類、複数の数値系列、色分け、合計・平均・中央値・最小・最大・件数を選択できます。数値軸は実際の数値間隔、日付軸は日時の間隔で描画します。フィルターはグループ内とグループ同士のAND/ORを指定できます。

独自指標は列キー `calc_...` と表示名、式、計算のタイミングで定義します。

| タイミング | 例 | 意味 |
|---|---|---|
| 行ごと | `likes / impressions * 100` | 作品ごとの率を求めてから集計 |
| 分類ごと | `sum(likes) / sum(impressions) * 100` | 分類内の合計から率を計算 |

四則演算、剰余、上限付き累乗、数値比較、AND/OR、条件式 `a if condition else b` と、`sum`、`mean`、`median`、`min`、`max`、`count`、`abs`、`round`、`sqrt`、`log`、`log10`、`coalesce` に対応します。計算列から参照できるのは先に定義した行単位の計算列です。Python・SQLを直接実行する機能はありません。

欠測・ゼロ除算・定義域外・非有限値の結果は欠測として扱います。明示的に欠測を補完したい場合は `coalesce` を使えます。計算式には長さ、構文木のノード数、関数、数値の大きさの制限があります。

折れ線では集計点に対して、増加数・増加率・移動平均を選べます。系列ごとに横軸を昇順に並べて計算します。「7点」の移動平均は7暦日ではなく7観測点です。最初の増加数・増加率と、分母がゼロの増加率は欠測です。

箱ひげ図はQ1・中央値・Q3、1.5×IQRの範囲内の端点と外れ値を表示します。通常の分位数は線形補間を使用し、重みが異なる場合は累積重みによる分位数を使用します。ヒストグラムは指定ビン数で、比較系列間に同じビン境界を使用します。分布には行単位の数値を使い、集計後の式は使用できません。

色・凡例・折れ線の数値ラベル・軸ラベル・数値横軸と縦軸の範囲・表示順を保存できます。図形はタップ・フォーカスで値を確認でき、グラフの下に数値テーブルも用意します。

## 複数キャラクター

`characters` と `artwork_characters` を追加します。互換性のため既存の `artworks.character` は代表値として保持し、既存の文字列を分割せず1キャラとして移行します。既存DBの変更は追加・冪等の移行とし、計測履歴は変更しません。

タグ対応表による自動入力を、新着検知、収集、手動URL登録、Notion移行の各経路で複数キャラに対応させています。`--character` の明示指定、作品詳細・テーブルでの手動設定は自動処理より優先します。手動で空にした状態も保護します。既存DBの移行時に入力済みだったキャラは手動設定として保護します。

テーブルでは登録済みキャラを複数選択でき、その場で新規追加もできます。元データのPATCH APIはキャラ以外の項目を拒否します。キャラの変更は2人共通のデータへ反映し、分析ビュー設定は個人のままです。

| 配分 | 件数・合計 | 平均・分位数 |
|---|---|---|
| 全量 | 各キャラに1作品分を計上 | 各キャラに全作品の値を使用 |
| 均等 | 1÷キャラ数の重みで配分 | 同じ重みによる加重統計 |
| 組み合わせ | キャラの組み合わせを1分類にする | 組み合わせごとに集計 |

配分はキャラが横軸または系列に指定されているときに適用します。円グラフの全量計上では重複があることを明示します。

## API

- `GET/POST /api/profiles`、`PATCH /api/profiles/{id}`
- `GET /api/analytics/metadata`
- `POST /api/analytics/query`
- `GET/POST /api/analytics/views`
- `PATCH/DELETE /api/analytics/views/{id}`
- `PATCH /api/artworks/{id}` に `{"characters": ["初音ミク", "巡音ルカ"]}`

分析APIは利用者一覧から選んだIDを `X-Analysis-Profile` ヘッダーで受け取り、その利用者の設定を読み書きします。未選択・存在しないIDは400です。選択中とは別の利用者のビューIDを直接指定しても更新・削除はできませんが、誰でも利用者を切り替えられます。更新には現在の `revision` が必要です。Cookie・CSRFトークン・秘密情報の設定は不要です。

公開の `/demo-api/metadata`、`POST /demo-api/query` は生成データだけを使用します。実データは読み書きしません。

## 検証とプロトタイプの範囲

```bash
pip install pytest
PYTHONPATH=. python -m pytest -q
```

Chromium/Playwrightブラウザーが利用できる環境では、ブラウザーテストも実行できます。

```bash
ANALYTICS_BROWSER_TESTS=1 PYTHONPATH=. python -m pytest tests/test_analytics_browser.py -q
# 必要なら PLAYWRIGHT_CHROMIUM_EXECUTABLE=/path/to/chromium を指定
```

APIテストでは本番DB・本番Notion・Xの実投稿は使いません。欠測、JST境界、配分、計算式の制限、加重統計、利用者別の設定、名前の追加・変更、別端末の切り替え、競合、旧DB互換性を検証します。ブラウザーではデモのPC/375px表示、軸の変更と再読み込み、キャラ編集、個人設定の分離、スマホの計算式編集、およびログインなしの実APIによる保存と切り替えを確認しています。

初期版の書き出し機能は含みません。上限は1ビュー12パネル、1パネル10計算列・6数値系列、1回の集計20,000行、グラフ2,500点です。期間はDB側でも絞り込みます。数値テーブルのグラフ代替表示は先頭200点、作品テーブルは50行ずつ表示します。

収集間隔、Notionへの保存、cron・本番プロセス設定はこの変更では更新しません。
