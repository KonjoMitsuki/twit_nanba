# データ分析プロトタイプ

既存のカレンダーとは別の `/analytics` に、Notion風の個人用分析スペースを追加します。FastAPI、SQLite、素のHTML/CSS/JavaScriptを使用し、グラフは外部CDNに依存しないSVGで描画します。

## まず画面を試す

```bash
pip install -r requirements.txt
APP_DB_PATH=./app.db PYTHONPATH=. python -m uvicorn api.main:app --host 127.0.0.1 --port 8000
```

`http://127.0.0.1:8000/analytics?demo=1` を開きます。デモは生成した作品・計測・フォロワー履歴のみを使用し、アプリDB・Notion・Xからデータを取得しません。作品テーブル、キャラクター別の伸び、ダッシュボードを操作できます。利用者A/Bの切り替えで設定の分離も確認できます。

デモの設定は利用者ごとにブラウザーのlocalStorageへ保存します。デモのキャラ編集は同じブラウザーのA/Bで共有します。

## ログインなしの利用者切り替え

実データは `http://127.0.0.1:8000/analytics` からそのまま利用できます。Googleアカウント・OAuth設定・許可メール・セッション秘密鍵は不要です。

サイドバーの利用者名で切り替えます。最初は「利用者A」「利用者B」を用意し、名前の変更と利用者の追加ができます。選択は端末に記憶し、ビュー設定は利用者ID別にSQLiteへ保存します。同じ利用者名を別端末で選ぶと同じビューを利用できます。名前を変えてもIDと保存済みビューは維持します。

**利用者名は設定を分けるためのもので、本人確認やアクセス制限には使いません。誰でも別の利用者を選び、その設定を表示・編集できます。** 作品データとキャラ編集は全利用者で共通です。

既存のカレンダー・作品取得・巡回操作にもログインは不要です。異なるサイトからのブラウザー経由の変更リクエストは拒否します。旧Google設定が環境変数に残っていても使用しません。以前のGoogle ID名義のビューを含め、既存レコードは削除しません。自動で新しい利用者に付け替える処理も行いません。

## ビューとダッシュボード

- テーブル、折れ線、棒グラフ、円、箱ひげ図、ヒストグラム、散布図を追加できます。
- 作品・計測ログのテーブルは投稿写真のサムネイルを先頭に表示します。写真から作品詳細を開け、複数画像の投稿は枚数を表示します。画像なし・読み込み失敗は文字で表示します。「軸」の「写真」で非表示にもでき、設定はビューに保存します。既存ビューにも標準で写真を表示します。
- テーブルの「軸」と「詳細」セクションでは、表示列の選択、投稿写真の表示、行のグループ化、最大5条件の昇順・降順の並べ替えをまとめて設定できます。グループ化ではキャラクター・タグ・日付などを選べ、条件は上から優先し、順番も変更できます。未設定の値は最後に表示します。
- パネル設定はモーダルを廃止し、PCの右ドック、タブレット・スマホの下部シートでプレビューと同時に操作します。「形式／データ／軸／絞り込み／見た目／計算式／詳細」を折りたたみできます。指標はチップと追加、単一指標はドロップダウンです。
- 「データ」の種類セグメントで作品・ログ・フォロワーを選び、1行の意味はⓘで確認します。各セクションの見出しで現在値を要約し、対象・未計測・除外件数はプレビューに表示します。
- 設定を変更するとヘッダーの「元に戻す」（最大20履歴、入力欄外ではCtrl/⌘+Z）で直前の変更を取り消せます。データ種類の変更で絞り込み・計算式がリセットされる場合は確認します。
- 「表・グラフを追加」は7形式のアイコンと名称だけを表示します。追加後すぐに設定を開き、あとから自由に変更できます。
- 条件に合うデータがない場合は、グラフ領域に「設定を見直す」「全期間にする」「絞り込みを解除」の案内を表示します。
- グループの順序、日付の単位（日・月曜始まりの週・月・年・元の値）、複数キャラやタグを各グループに表示するか組み合わせでまとめるかを選べます。日付の区切りは日本時間です。設定とグループの折りたたみ状態（最大2,000グループ）は利用者別のビューに保存します。複数グループに同じ行が属する場合も全体の行数は重複計上しません。
- 単独表示ではパネルをタブで切り替え、ダッシュボードでは同時に並べます。
- パネルは上下ボタンで並べ替えられます。ドラッグ操作は必須ではありません。
- ビュー名、各パネルのデータ・軸・系列・計算・見た目は個人ごとに保存します。変更は自動保存されません。ヘッダーの「保存」（Ctrl/⌘+S）で、未保存のビューをまとめて保存します。
- ビューの作成・複製・削除ができます。ビュー削除で作品や計測は削除されません。
- ビューはロックできます。ロック中はビュー名・レイアウト・パネル設定・並べ替え・削除を変更できません。ツールバーの鍵ボタンで解除します。ロック状態は利用者ごとのビューに保存され、別端末でも引き継がれます。
- 保存した条件を開くたび、現在のデータを再集計します。「直近30日」などの相対期間も保存できます。
- 未保存のビューはサイドバーに印を表示し、ページを閉じる前に確認します。保存に失敗した場合は未保存と表示し、再度「保存」で再試行します。「更新」はデータの再集計のみを行い、設定は保存しません。
- 未保存の下書きは利用者ごとにブラウザーにも保持し、再読み込み後に復元します。同じビューを別タブで変更した場合はrevisionを検証し、自動で上書きせず、変更を別ビューに保存するか保存済み設定を使うかを選べます。
- 利用者を切り替える前に、未保存の変更を保存してください。
- PC・スマホとも同じ設定項目を編集できます。スマホの設定は高さを切り替えられるボトムシートで表示し、選択中のグラフを上部に残します。

## データの粒度と時間

| データ種類 | 1行の意味 | 期間の基準 |
|---|---|---|
| 作品ごと | 1作品の指定した計測ステージ | 投稿日（JST） |
| 計測ログ | 1作品の1計測 | 投稿日（JST） |
| フォロワー履歴 | アカウント全体の1計測 | 計測日（JST） |

作品比較の時点は `config.SCHEDULE_STAGES` から選択します。24hが指定されている場合、24hの計測がない作品に1hや最新値を代入しません。テーブルでは未計測と表示し、グラフでは除外件数を表示します。元データの数値をゼロで補ったり書き換えたりしません。

フォロワー履歴は `account_metrics` を使用します。作品のスナップショットに含まれるフォロワー数を、特定のキャラによる獲得数として帰属させません。

開始日・終了日は両端を含みます。終了日の指定がなければJSTの当日を使用します。明示した開始日を優先し、なければ「直近の日数」を使用します。開始日も日数も指定しない場合は全期間です。

前期間比較では同じ長さの直前の期間を別系列として表示します。日付軸では前期間の日付を現在の期間へシフトして重ねます。元の保存日時は変更しません。前期間比較は折れ線・棒グラフ・箱ひげ図・ヒストグラムに対応します。

## 計算とグラフ設定

横軸・分類、複数の数値系列、色分け、合計・平均・中央値・最小・最大・件数を選択できます。数値軸は実際の数値間隔、日付軸は日時の間隔で描画します。フィルターはグループ内とグループ同士のAND/ORを指定できます。

独自指標は列キー `calc_...` と表示名、式、計算のタイミングで定義します。

| タイミング | 例 | 意味 |
|---|---|---|
| 行ごと | `likes / impressions * 100` | 作品ごとの率を求めてから集計 |
| 分類ごと | `sum(likes) / sum(impressions) * 100` | 分類内の合計から率を計算 |

四則演算、剰余、上限付き累乗、数値比較、AND/OR、条件式 `a if condition else b` と、`sum`、`mean`、`median`、`min`、`max`、`count`、`abs`、`round`、`sqrt`、`log`、`log10`、`coalesce` に対応します。計算列から参照できるのは先に定義した行単位の計算列です。Python・SQLを直接実行する機能はありません。

欠測・ゼロ除算・定義域外・非有限値の結果は欠測として扱います。明示的に欠測を補完したい場合は `coalesce` を使えます。計算式には長さ、構文木のノード数、関数、数値の大きさの制限があります。

折れ線では集計点に対して、増加数・増加率・移動平均を選べます。系列ごとに横軸を昇順に並べて計算します。「7点」の移動平均は7暦日ではなく7観測点です。最初の増加数・増加率と、分母がゼロの増加率は欠測です。

箱ひげ図はQ1・中央値・Q3、1.5×IQRの範囲内の端点と外れ値を表示します。通常の分位数は線形補間を使用し、重みが異なる場合は累積重みによる分位数を使用します。ヒストグラムは指定ビン数で、比較系列間に同じビン境界を使用します。分布には行単位の数値を使い、集計後の式は使用できません。

色・凡例・折れ線の数値ラベル・軸ラベル・数値横軸と縦軸の範囲・表示順を保存できます。図形はタップ・フォーカスで値を確認でき、グラフの下に数値テーブルも用意します。

ホイール・ピンチはX軸だけをズームします。描画域のドラッグはX軸をパンし、「Y自動」を解除するとY軸もパンします。X軸とY軸の目盛りをドラッグして独立に拡縮できます。「Y自動」は自動・手動を切り替え、Y軸ダブルクリックで保存した最小・最大設定を考慮した自動状態へ戻ります。データ更新時は操作範囲を維持します。詳細は [グラフ操作・実装調査・検証](analytics-chart-interactions.md) を参照してください。

## 複数キャラクター

`characters` と `artwork_characters` を追加します。互換性のため既存の `artworks.character` は代表値として保持し、既存の文字列を分割せず1キャラとして移行します。既存DBの変更は追加・冪等の移行とし、計測履歴は変更しません。

タグ対応表による自動入力を、新着検知、収集、手動URL登録、Notion移行の各経路で複数キャラに対応させています。`--character` の明示指定、作品詳細・テーブルでの手動設定は自動処理より優先します。手動で空にした状態も保護します。既存DBの移行時に入力済みだったキャラは手動設定として保護します。

テーブルのキャラクター編集では、選択中のキャラクターをチップで表示します。未入力時の候補は使用作品数が多い順に最大5件を表示し、入力欄に文字を入れると一致する候補（前方一致・部分一致）を最大5件に絞って表示します。候補にない名前は入力欄から新規追加できます。

テーブルでは登録済みキャラを複数選択でき、その場で新規追加もできます。元データのPATCH APIはキャラ以外の項目を拒否します。キャラの変更は2人共通のデータへ反映し、分析ビュー設定は個人のままです。

| 配分 | 件数・合計 | 平均・分位数 |
|---|---|---|
| 全量 | 各キャラに1作品分を計上 | 各キャラに全作品の値を使用 |
| 均等 | 1÷キャラ数の重みで配分 | 同じ重みによる加重統計 |
| 組み合わせ | キャラの組み合わせを1分類にする | 組み合わせごとに集計 |

配分はキャラが横軸または系列に指定されているときに適用します。円グラフの全量計上では重複があることを明示します。

## API

- `GET/POST /api/profiles`、`PATCH /api/profiles/{id}`
- `GET /api/analytics/metadata`（キャラクター候補と使用作品数 `character_counts` を含む）
- `POST /api/analytics/query`
- `GET/POST /api/analytics/views`
- `PATCH/DELETE /api/analytics/views/{id}`
- `PATCH /api/artworks/{id}` に `{"characters": ["初音ミク", "巡音ルカ"]}`

分析APIは利用者一覧から選んだIDを `X-Analysis-Profile` ヘッダーで受け取り、その利用者の設定を読み書きします。未選択・存在しないIDは400です。選択中とは別の利用者のビューIDを直接指定しても更新・削除はできませんが、誰でも利用者を切り替えられます。更新には現在の `revision` が必要です。Cookie・CSRFトークン・秘密情報の設定は不要です。

公開の `/demo-api/metadata`、`POST /demo-api/query` は生成データだけを使用します。実データは読み書きしません。

### グラフの操作と目盛り

折れ線・棒グラフ・散布図・箱ひげ図・ヒストグラムは、グラフ本体をドラッグまたは1本指でスワイプして表示範囲を移動できます。ホイール、2本指のピンチ、＋/−ボタンで拡大・縮小し、縦横の目盛りと図形の座標も更新します。全体表示の範囲内で最大1,000倍まで拡大できます。最初に拡大してから移動してください。「表示範囲をリセット」またはダブルクリックで設定した範囲に戻ります。ズーム・移動は閲覧中の一時的な状態で、ビューの保存範囲は変更しません。データ更新・設定変更・再読み込みでは設定した範囲に戻ります。

カーソルを置くと値を表示します。折れ線は近い横軸の観測点に十字線とマーカーを表示し、その横軸にある各系列の値をまとめます。キャラクターなどの系列を比較する折れ線では作品カードを省き、時点ごとの系列名・統計量・集計件数を表示します。スマートフォンではグラフをタップすると吹き出しを固定でき、長い一覧は吹き出し内を縦スクロールして読めます。吹き出しの外をタップすると閉じます。「値を見る」に切り替えると、なぞって値を確認できます。「移動」に戻すと1本指のスワイプで移動できます。円グラフも各区分に指やカーソルを置くと値と割合を確認できます。凡例で非表示にした系列はツールチップからも除外します。キーボードではグラフにフォーカスし、左右キーで値、＋/−でズーム、Homeまたは0でリセット、Escapeでツールチップを閉じられます。

View Settingsの「詳細」で横軸・縦軸それぞれの「目盛り間隔」をAutoか数値指定から選びます。Autoは表示範囲と幅から間隔を決めます。数値軸は値の差、分類軸は項目数、日付軸は日・時間・分・秒の間隔で指定します。日付は日本時間で表示・整列します。正の数だけを受け付け、極端に細かい指定では描画を維持するため一部の目盛りを省略します。間隔の設定は利用者別のビューに保存します。円グラフ・テーブルには軸の間隔設定はありません。

### 投稿ごとのプレビューカード

散布図や、1つの観測行に対応する折れ線の点では、指・カーソル・キーボードフォーカスで投稿カードを表示します。左に投稿画像、右に作品名・いいね数・リポスト数を並べ、計測ステージと日時も表示します。複数画像は最初の画像と枚数を表示します。画像なし・読み込み失敗は代替表示、未計測の数値は「未計測」とし、0はそのまま表示します。

カードの数値はその点に対応する計測時点の値を使い、最新値で補完しません。同じ点の複数系列・複数指標で同じ投稿を示す場合はカードをまとめます。複数の行を集計した点、箱ひげ図・ヒストグラムの分布、フォロワー履歴は投稿カードを表示しません。複数行が同じ投稿に属する場合も、集計値を1つの計測と誤認させないため通常の数値表示を使います。

### 棒グラフ

棒グラフは、キャラクター・タグ・日付などの分類ごとに集計値を並べ、値の大小を比べます。棒は0を基準に描き、負の値は0から下向きに伸ばします。複数の数値系列や系列・色分けがある場合は、同じ分類の中に棒を横並びで表示し、分類の区切りが分かるよう棒の間に間隔を空けます。ヒストグラムと違い、横軸は連続した数値区間ではなく分類です。

「軸」で横軸と縦軸（最大6指標）を、「詳細」で系列・集計を指定します。「詳細」の「表示順」で横軸順または値の大きい順・小さい順に並べ替えられます。前期間比較、数値ラベル、ズーム・移動に対応します。横軸は分類軸のため横軸の範囲固定は使わず、縦軸の範囲は固定できます。

棒グラフは集計点を表示するため、作品ごとの投稿カードは表示しません。値はツールチップと下の数値テーブルで確認できます。集計後の増加・移動平均は折れ線グラフでのみ使用できます。

### 散布図

「形式」で「散布図」を選び、「軸」で横軸（数値・日付・行ごとの計算列）、縦軸（数値・行ごとの計算列、UIは単一選択。既存の複数指標は変更するまで保持）を指定し、「詳細」で系列を選びます。各行を1点として表示し、同じ横軸の値を持つ行も集計しません。作品ごとでは指定時点、計測ログでは各計測、フォロワー履歴では各観測を点にします。座標が未計測・計算不能な行は除外し、ゼロはそのまま表示します。

点をタップまたはキーボードでフォーカスすると作品名・座標・系列を確認できます。凡例で系列を切り替え、下の数値テーブルでも値を確認できます。複数キャラは各キャラの系列に同じ座標で表示するか、組み合わせで色分けします。座標をキャラ数で配分する処理は行いません。「見た目」で色・凡例、「詳細」で軸名・範囲を設定でき、個人のビューに保存します。散布図は前期間比較・集計後の計算・集計後の増加/移動平均には対応しません。上限は他のグラフと同じ2,500点です。

## 検証とプロトタイプの範囲

```bash
pip install pytest
PYTHONPATH=. python -m pytest -q
node tests/test_analytics_table.cjs
node tests/test_analytics_chart_interactions.cjs
node tests/test_analytics_characters.cjs
```

Chromium/Playwrightブラウザーが利用できる環境では、ブラウザーテストも実行できます。

```bash
ANALYTICS_BROWSER_TESTS=1 PYTHONPATH=. python -m pytest tests/test_analytics_browser.py -q
# 必要なら PLAYWRIGHT_CHROMIUM_EXECUTABLE=/path/to/chromium を指定
```

APIテストでは本番DB・本番Notion・Xの実投稿は使いません。欠測、JST境界、配分、計算式の制限、加重統計、利用者別の設定、名前の追加・変更、別端末の切り替え、競合、旧DB互換性を検証します。ブラウザーではデモのPC/375px表示、短い設定要約・データ種類セグメント・元に戻す、手動保存と未保存表示、ビューのロックと解除、軸の変更と再読み込み、キャラ編集、個人設定の分離、スマホの計算式編集、およびログインなしの実APIによる保存と切り替えを確認しています。

全ビューリセットにはJSONバックアップを用意します。集計データの書き出し・バックアップJSONの自動インポートは含みません。上限は1ビュー12パネル、1パネル10計算列・6数値系列、1回の集計20,000行、グラフ2,500点です。期間はDB側でも絞り込みます。数値テーブルのグラフ代替表示は先頭200点、作品テーブルは50行ずつ表示します。グループ化した場合は全対象行からグループを作成し、10グループずつ、各グループ内は50行ずつページを切り替えます。

収集間隔、Notionへの保存、cron・本番プロセス設定はこの変更では更新しません。

計算式の四則演算・累乗は有限の数値だけを対象とし、中間結果も絶対値1e100以内に制限します。集計前の配列に対する直接の掛け算・足し算は行わず、sum・meanなどの集計関数で数値に変換してから計算します。制限を超えた結果は未計測として扱います。

## ビュー設定のリセット

パネル初期化とテンプレートからのビュー再作成は、保存まで下書きです。ヘッダーの「破棄」は現在のビューを最後の保存状態へ戻します。全ビューリセットはJSONダウンロードと件数入力後に、対象利用者のロックされていないビューだけを既存DELETE APIで順番に削除します。他利用者・作品・計測履歴には触れません。

設定UIは `analytics-settings.js`、画面全体のビュー・下書き・保存・パネル描画は `analytics.js`、追加スタイルは `css/analytics-settings.css` にあります。保存形式はversion 1のままで、DB/API/集計/収集処理の変更はありません。幅・ドラッグ並べ替え・やり直し（任意項目）は今回追加していません。

## 情報量の削減（仕様書 §3.0 改訂）

新規パネルの常設項目は5〜6個で、形式はアイコンのみ、期間はプリセットを使う。説明・補足はⓘのポップオーバーへ移し、常設しない。名前・系列・集計・変換・配分・比較・軸・目盛り・表の整理は「詳細」へ集約した。「見た目」は色・凡例・数値、「計算式」は空なら追加ボタンだけを表示する。パネル追加は7形式のアイコンと名称だけで、用途テンプレートは併記しない。

文字数の測定条件、変更前後の数値、全設定項目と文言の移動先は [情報量レビュー](analytics-settings-density-review.md) を参照。既存の保存値・APIは変えず、表示位置だけを変更している。
