# 分析グラフのズーム・パン

対象は `/analytics#views` の分析グラフです。ダッシュボード概要の月別棒グラフと作品詳細ページのグラフは別実装です。

## 調査と選定

既存実装は `web/analytics-charts.js` と `web/analytics-chart-interactions.js` による独自SVGです。外部チャートライブラリもライブラリのバージョン指定もありません。Vanilla JavaScript、CSS変数、既存の色・フォントを継続使用します。

- `analytics.js` がパネル設定を `/api/analytics/query`（デモでは `/demo-api/query`）へPOSTし、取得した結果をパネル単位でキャッシュします。グラフ操作は取得済みデータだけを使用します。
- 従来のホイール／ピンチはXY両軸を同時に拡縮し、描画域のドラッグは両軸をパンしていました。軸ごとの直接操作はありませんでした。
- 従来のクロスヘアは折れ線の最寄り観測点に縦線を表示する方式でした。複数系列の値、作品画像、欠測、凡例による表示切替、キーボード操作、集計データ表があります。
- View Settings の `style.y_min/y_max`、軸目盛り間隔、色、ラベル、凡例などは永続設定です。従来は結果オブジェクトやstyleの変化で表示範囲をリセットしていました。
- グラフ間の同期操作は追加していません。各パネルの時間範囲は独立しています。モバイルは「移動」「値を見る」のモード切替とピンチに対応していましたが、`touch-action:none` が縦スクロールを妨げていました。
- 分析ページの既存CSSにはダークモードの切替定義はありません。テーマや背景色は変更せず、新しい軸表示も既存CSS変数に従います。

以下は既存コードへの適合性をもとにした移行評価です。移行先ライブラリの実装・ベンチマーク比較は行っていません。

| 選択肢 | 操作感と互換性 | 性能と移行コスト | 判断 |
|---|---|---|---|
| 既存SVGの拡張 | 既存の7種類の表示、軸設定、作品カード、欠測、凡例、データ表を維持し、必要な操作を追加できる | 軸計算と入力処理の変更で済む。大量の折れ線は表示範囲の抽出と描画点の間引きが必要 | 採用。依存追加なしで要件を満たせる |
| TradingView Lightweight Charts | 時間・数値軸のドラッグ、ホイール、ピンチ、軸ダブルクリックなどの標準操作が今回の目的に近い | 時系列中心の構成へ変換し、箱ひげ図・分類軸・既存カード・アクセシビリティ等を再統合する必要がある。移行コスト大 | 将来、時間チャートを独立させる場合の候補 |
| Apache ECharts | 多様な分析グラフとdataZoomがあり、既存の分析種類に合わせやすい。今回の軸直接ドラッグ等の操作仕様は追加の調整が必要 | 既存SVGの描画・ツールチップ・設定をoptionへ移植する範囲が広い。大量データ描画の候補だが今回の変更範囲を超える | 分析チャート全体を刷新する場合の候補 |

参照: [Lightweight Charts HandleScaleOptions（参照時5.2）](https://tradingview.github.io/lightweight-charts/docs/api/interfaces/HandleScaleOptions)、[時間軸の実装](https://github.com/tradingview/lightweight-charts/blob/master/src/model/time-scale.ts)、[数値軸の実装](https://github.com/tradingview/lightweight-charts/blob/master/src/model/price-scale.ts)、[Apache ECharts dataZoom](https://github.com/apache/echarts-doc/blob/master/en/option/component/data-zoom-inside.md)。軸ドラッグの方向はこれらの実装を参考にし、X軸は左／Y軸は上へのドラッグで表示を拡大します。

## 操作

| 操作 | 動作 |
|---|---|
| 描画域でホイール | カーソル位置を中心にX軸だけを拡縮 |
| 描画域でドラッグ／1本指のスワイプ | 自動YではX軸だけ、手動YではX軸とY軸をパン。タッチ・マウス共通 |
| X軸目盛りを左右ドラッグ | 右端を固定して時間スケールを変更。左で拡大、右で縮小 |
| Y軸目盛りを上下ドラッグ | 手動Y時のみ、表示範囲の中央を固定し、上で拡大、下で縮小。自動Yでは無効 |
| 描画域またはX軸をダブルクリック | X軸を初期範囲へ戻す。手動Yは維持 |
| 「Y自動」をクリック | 自動／手動を切り替え。手動へ切り替えた時点のY範囲を保持 |
| Y軸をダブルクリック | 自動Yに戻し、現在のX範囲に合わせて再計算 |
| 描画域で2本指のピンチ | 指の中点を中心に、自動YではX軸だけ、手動YではXY両軸を拡縮。中点移動によるパンも同様 |
| 1本指の縦スワイプ | 描画域の「移動」＋手動YではY軸をパン。自動Yでは上下移動は無効。「値を見る」またはグラフ外ではページをスクロール |
| 「値を見る」＋横になぞる | 範囲を変えずに値を確認 |
| ＋／−ボタン、キーボード＋／− | X軸を中心から拡縮 |
| Shift＋左右矢印 | X軸を表示幅の10%だけ移動 |
| 左右矢印／Escape | 観測点の値を順番に確認／クロスヘアを閉じる |
| 「表示範囲をリセット」／Home／0 | X初期範囲とY自動に戻す |

ホイールと軸ドラッグは指数係数で連続的に変化します。X軸の拡大上限は元の範囲の1/1000、縮小上限は元の全範囲です。パンはデータ範囲（数値軸では保存した範囲も考慮）に制限し、無限の空白へは移動しません。手動Yは元の数値幅の1/10000〜10000倍を目安に制限し、浮動小数点の精度も考慮します。

操作する領域は指を置いた位置で決まり、指を離すまで維持します。X軸から描画域へ指が移動してもX軸ズーム、Y軸から移動してもY軸ズームを続けます。2本指のピンチは両方の指を描画域に置いて始めてください。設定プレビューなどでSVGの縦横比が変わっても、描画の余白を含む実際の座標変換で領域を判定します。

## Y軸と保存設定

初期状態は自動です。折れ線と日時グラフは表示中の値に余白をつけます。折れ線が範囲端をまたぐ場合は境界で補間した値も含めます。欠測区間はつなぎません。棒などの分類・分布グラフではゼロ基準を維持します。一定値には余白を設け、表示範囲が空／全系列が非表示の場合は安全な既定範囲を使います。

View Settings に最小値・最大値がある場合、自動状態はその指定を優先します。Y軸の手動操作は一時的に指定を上書きします。「Y自動」は押すたびに自動／手動を切り替え、Y軸ダブルクリックでは自動に戻ります。手動Yでは描画域の上下ドラッグで数値軸をパンできます。「Y自動」オンでは、Y軸スワイプ・上下パン・ピンチによるY方向の拡縮は無効です。操作から手動Yへ自動で切り替えません。X範囲を変えると、表示中のデータに合わせてY範囲を自動調整します。Y方向を操作する場合は、先に「Y自動」をオフにしてください。「値を見る」のときは縦スワイプでページをスクロールできます。グラフ外から始めたスワイプでもページをスクロールできます。操作で保存設定を書き換えたり未保存表示にしたりはしません。設定画面でY最小／最大を変更した場合は、変更を反映するため自動状態へ戻ります。

同一ビュー内のデータ更新、パネル再描画、画面サイズ変更、色などの外観変更では操作範囲を維持します。追加データが来てもズームした範囲はそのままです。全範囲のまま操作していない場合は、新しい全範囲を表示します。データ範囲が狭くなった場合は収まるように制限します。チャート種類・データ種類・X/Y指標・変換・系列・X範囲設定を変更すると範囲を初期化します。操作状態は保存対象に含めず、ページ再読み込みや別ビューへの移動では初期状態になります。

## クロスヘア

クロスヘアは観測点へスナップせずカーソルに追従し、縦横の線、X軸上の日時（JST）／値、Y軸上の値を表示します。系列を比較する折れ線のツールチップには、時点・指標・統計量、各系列の値と集計件数を表示し、作品カードは表示しません。スマートフォンではグラフのタップで吹き出しを固定し、吹き出し内を縦スクロールできます。外側をタップすると閉じます。作品単位で見る折れ線や散布図では、作品画像・画像枚数・いいね・リポストなどのカードを保持します。カーソルの座標値と観測点の値は異なる場合があります。


## 描画と検証

入力をrequestAnimationFrameでまとめ、フレーム間のホイール入力も直前の操作結果へ累積します。操作中はAPIを呼ばず、SVGの描画内容だけを更新します。SVG本体・入力面・ツールバー・集計データ表を保持し、タッチの継続、フォーカス、データ表の開閉状態を保ちます。リスナーはチャートホストごとに一度登録します。切り離されたホストの予約フレームは描画しません。

View Settingsを閉じる際は、予約済みのプレビュー更新をその場で反映します。閉じた後に遅延更新がパネルを作り直し、開いたメニューやチャート操作を中断するタイミング問題も修正しています。

折れ線は表示範囲の両隣を含めて二分探索で抽出し、密な領域は画素列ごとの先頭・末尾・最小・最大を描画します。原データ、自動Yの極値、ツールチップの値は間引きません。密な線の点マーカーと数値ラベルは省略し、拡大すると再表示します。大量の欠測による断線は維持します。

```bash
node tests/test_analytics_chart_interactions.cjs
ANALYTICS_BROWSER_TESTS=1 PYTHONPATH=. .venv/bin/python -m pytest tests/test_analytics_chart_browser.py tests/test_analytics_browser.py -q
PYTHONPATH=. .venv/bin/python -m pytest -q
```

合成データと隔離DBで検証します。Chromiumでは実マウス入力とCDPのタッチ入力を使用し、375px縦画面・844px横画面の縦スクロール、ピンチ、パン、ツールチップ収まりを確認します。5万点の折れ線については12回の表示範囲更新時間、DOM要素数、API呼出なし、要素の再利用、集計表の開状態をテストします。

実機のiOS Safari／Androidブラウザーと全端末での60fpsは保証していません。大量点の最適化は折れ線を対象とし、散布図・棒などの大規模データの描画方式は従来通りです。

### この変更の検証記録

今回の操作領域・Y自動の制御修正後は、Python 3.12の環境で関連ブラウザーテスト31件とNode.jsの軸計算テストが成功しました。グラフ操作28件、画面全体の統合1件、設定シートの関連2件です。375px縦画面・844px横画面の通常表示・実際の設定プレビューと、SVGの縦横比を変えた表示で、軸別ズーム、開始領域の維持、追加の指による操作の横取り防止、ピンチによる両軸ズーム、上下左右パン、グラフ外／「値を見る」でのページスクロールを確認しています。Y自動オンでY軸スワイプ・上下パンが無効になり、ピンチはX軸だけに作用してY自動を維持すること、オフでY操作が有効になり再びオンで無効になることも確認しています。軸境界のデータ点を軸操作と誤判定しないこと、狭い画面のタッチ対象補正でも軸操作を維持すること、作品カード表示も回帰テストで確認しました。実機のiOS Safari／Androidでは未確認です。

以前の全体検証環境はChromium 155.0.8059.79、Node.js 22.22.3、Python 3.10.12です。今回の追加テストはChromium 153.0.8010.12、Python 3.10.12で実行しました。プロジェクトで指定しているPython 3.12での再実行、実機Safari／Androidの確認は行っていません。

Y自動ボタンの切替と手動Yパンを追加した後は、該当するブラウザーテスト4件を再実行して成功しました。自動から手動への切替、マウスの上下パン、ホイール・Xリセット後のY範囲保持、Y軸ダブルクリックでの自動復帰、スマートフォン相当の横スワイプ中のYパンを確認しています。以下はそれ以前の全体検証記録です。

- グラフ操作のブラウザーテスト15件が成功しました。マウス・タッチ・軸・状態保持・大量データに加え、入力リスナーの重複防止と、データ点上で開始したタッチドラッグの継続も対象です。
- 隔離サーバーの統合テストでは、更新ボタンによるホスト再作成後もX範囲と手動Yを維持し、保存状態が変わらないことを確認しました。
- グラフ・統合・設定・レイアウト・密度テストの一式は53件成功、2件スキップ、下記の既存バックアップテスト2件を除外しています。ブラウザーで確認した成功テストは計51件です。320〜1440pxの表示、既存のView Settings、全グラフ種類、作品カード、保存・切替・ロック、設定プレビューを確認しました。
- 通常のpytestは76件成功、Node.jsの軸計算・テーブル・キャラクターのテストも成功しています。
- 既存のバックアップダウンロードテスト2件は、ダウンロード内容のJSON読み込みで失敗します。`git archive HEAD`から作った変更前の隔離コピーでも同じ失敗を再現したため、この変更の対象外です。
- 5万点の12回の表示範囲更新は、この環境で中央値約10〜14msでした。初回・GC等による遅いフレームもあるため、固定の60fpsを保証する結果ではありません。SVG要素は26個で、元の5万点とツールチップ用データを保持しています。
