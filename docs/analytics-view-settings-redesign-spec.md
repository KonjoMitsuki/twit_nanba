# 分析画面 ビュー設定UI 刷新仕様書

対象リポジトリ: `KonjoMitsuki/twit_nanba`
対象ブランチ: `ui/analytics-customizable-redesign`(ここから分岐して作業する)
推奨配置: `docs/analytics-view-settings-redesign-spec.md`

> 実装エージェントへ: 最初に `AGENTS.md` を読むこと。本書はUI刷新の依頼であり、`AGENTS.md` の「再設計の依頼がない限り現行UIの方向性を維持する」の例外として(本書が再設計の依頼にあたる)、**分析画面(`/analytics`)に限り構造レベルの刷新を許可する**。それ以外の規則(vanilla構成、データ整合性、テスト方針、セキュリティ)は全て維持する。

## 1. 背景と目的

現行の分析画面は「ビュー → パネル → 設定」を細かくカスタマイズできるが、**設定の操作が重く、使いづらい**。直前のデザイン改修(`docs/analytics-ui-redesign.md`)はCSSのみの調整で、操作構造は変わっていない。

今回は見た目の調整ではなく、**設定の操作体系そのものを作り直す**。あわせて、設定を初期状態へ戻す「リセット」機能を整備する。

### 1.1 現行の問題点(コードと文書から確認した事実)

| # | 問題 | 根拠 |
|---|---|---|
| P1 | 設定がモーダルダイアログで、**変更中にグラフが見えない**。設定→閉じる→確認、の往復が必要 | `web/analytics.html` の `#settings`(dialog)、`docs/analytics-user-guide.md` |
| P2 | 設定が内部実装由来の5タブ(基本/表示/絞り込み/見た目/詳細)。「何をしたいか」で探せず、チャート種別に無関係な項目も出る | `.settings-tabs`、`renderSettings()`(約400行) |
| P3 | 縦軸の指標選択などが**チェックボックスの大きなグリッド**で、縦に長く、全体像が把握しづらい | `docs/images/analytics/settings.jpg` |
| P4 | 保存まわりが分散・曖昧。ヘッダーの「保存」、設定下部の「保存」「閉じる」「元に戻す」、ロック、Ctrl+S、下書き復元が併存し、**「閉じる」では保存されない**ことが分かりにくい | `#save-view` `#save-settings` `#done-settings` `#undo-settings` |
| P5 | **リセット手段がない**。パネル単位・ビュー単位とも、初期状態へ戻すには手作業で全項目を戻すか、ビューを作り直すしかない | 現行実装に該当機能なし |
| P6 | 単一ファイルが巨大(`web/analytics.js` 2,918行、`web/css/analytics.css` 2,967行)。設定UIの変更コストが高い | `wc -l` |
| P7 | パネルごとの幅・ドラッグ並べ替えがなく、配置の自由度が低い(上下ボタンのみ) | `docs/analytics-ui-redesign.md` |
| **P8(最重要)** | **設定パネルの情報量・文字数が多すぎる**。各項目に見出し+説明文+補足が付き、全項目が最初から並ぶため、画面が文字で埋まり、目的の項目を探せない。上記P1〜P4の根本原因の一つ | `docs/images/analytics/settings.jpg`(「軸の設定」→説明文→「横軸・分類」→補足文…と、項目より説明のほうが多い) |

### 1.2 ゴール

0. **設定パネルの情報量・文字数を大幅に減らす**(§3.0。本刷新の最優先事項)。
1. **設定しながらグラフが見える**(設定とプレビューの同時表示)。
2. **チャート種別に応じて、必要な項目だけを表示**する。
3. 設定を**目的別に整理**し、よく使う項目を最短操作で変えられる。
4. **保存・元に戻す・リセットの操作体系を1か所に統一**する。
5. **パネル/ビュー単位のリセット**を安全に提供する。
6. 上記を実現しつつ、**既存の保存データ・API・集計ロジックは壊さない**。

### 1.3 非ゴール(今回やらないこと)

- React / Next.js / Tailwind / 他フレームワークへの移行。**vanilla HTML/CSS/JS を維持**。
- 集計ロジック(`processing/analysis.py`)の変更、計算式の関数・演算子の追加。
- DBスキーマ変更、既存ビューの自動削除・自動書き換え。
- ダークテーマ、利用者認証の導入。
- 収集系(`scraper/`、`main.py`、Notion連携)の変更。

## 3. 新しい情報設計

### 3.0 最優先の設計原則:情報量と文字数を減らす(P8)

**本刷新の第一目的は、設定パネルの情報量・文字数の削減である。** 以降の全仕様(§3.1〜)は、この原則に反しない範囲で解釈すること。迷ったら「足す」より「消す・隠す」を選ぶ。

| # | 原則 | 具体ルール |
|---|---|---|
| R1 | **説明文を常時表示しない** | 項目の説明文・補足文・例示文は、画面に常設しない。必要なものだけ、項目名の横の `ⓘ` を押したときのポップオーバー(またはツールチップ)に出す。**入力欄の直下の補足文は全廃**する |
| R2 | **ラベルは短く** | 項目ラベルは原則 **8文字以内**(例:「横軸」「縦軸」「系列」「集計」「期間」)。「横軸・分類」「集計指標の選択」「系列と集計」のような複合見出し・説明的な見出しは使わない。セクション名も2〜6文字(「形式」「データ」「軸」「絞り込み」「見た目」「計算式」) |
| R3 | **重複する見出しを作らない** | 「軸の設定」→「横軸・分類」→「横軸」のように、同じ内容を示す見出しを多重にしない。**セクション見出し + 入力ラベル の2階層まで**。小見出し・区切り文・サブ説明は置かない |
| R4 | **既定のままの項目は隠す** | 値が既定のままの上級項目は、折りたたんだ「詳細」の中に置く。初期表示の常設項目は **表示形式ごとに最大6個** を目標とする(§3.3の表の「基本」列) |
| R5 | **段階的開示** | 常に開くのは「形式」「データ」「軸」の3セクションのみ。「絞り込み」(条件があるときだけ開く)・「見た目」・「計算式」・「詳細」は閉じて、見出しだけ表示する |
| R6 | **要約は短く** | 閉じたセクションの現在値要約は **1行・約20文字以内**(例:「作品 · 30日」)。現行の長い設定サマリー(`#settings-summary` の複数行文)は廃止する |
| R7 | **選択肢は文字より形** | チャート種別・期間・集計などは、アイコンや短いセグメントで選ぶ。選択肢ごとの説明文は置かない |
| R8 | **ボタン・メッセージも短く** | ボタンは動詞1語〜2語(「保存」「破棄」「追加」「リセット」)。確認文・エラー文は **1文**(最大でも2文)。長い注意書きはダイアログ内のみとし、設定ペインに常設しない |
| R9 | **空の状態を最小に** | 条件・計算式・並べ替えが0件のときは、説明文ではなく `+ 追加` ボタン1つだけを出す |

**数値目標(受け入れ基準に使う)**: 初期状態(新規パネル、折れ線)で、設定ペインを開いたときの
- 常時表示される**文字数は現行比で半分以下**(実装前に現行の同条件の文字数を計測して記録し、実装後と比較すること。DOMのテキスト長で可)
- 常設の入力項目は6個以下、**説明文・補足文は0個**
- スクロールなしで(PCの高さ800px、モバイルの展開時)「形式・データ・軸」の3セクションが一画面に収まること

### 3.1 全体レイアウト

```
PC (>=1024px)
┌────────────┬──────────────────────────────┬───────────────────┐
│ MY VIEWS   │ ビュー名  [ロック] [保存状態] │ パネル設定         │
│ (折りたたみ)│ ┌─────────┐ ┌─────────┐      │ (右ドック・常設)   │
│            │ │ パネル1 │ │ パネル2 │      │ 選択中パネルを     │
│            │ └─────────┘ └─────────┘      │ その場で編集       │
└────────────┴──────────────────────────────┴───────────────────┘

モバイル (<768px)
┌───────────────────┐
│ ビュー切替 ▾  保存 │
│ パネル(プレビュー) │  ← 上部に常時表示(画面高の約40%)
├───────────────────┤
│ 設定ボトムシート   │  ← ドラッグで拡大/縮小
└───────────────────┘
```

- **P1の解消**: 設定はモーダルではなく、PCは右ドック、タブレットはパネル下の固定ドロワー、モバイルはボトムシート。パネルを選ぶ(クリック/タップ)とそのパネルの設定が開く。**設定中もグラフはリアルタイムで再描画**する(既存の `query` 呼び出しをデバウンスして使う。250〜400ms程度)。
- 設定を開いていない状態でもダッシュボードの閲覧が主役であること。設定ドックは閉じられる。
- ドックの開閉状態はビューの保存対象外(端末ごとのUI状態としてlocalStorage可。既存キーと衝突させない)。

### 3.2 設定の構成(P2/P3の解消)

5タブを廃止し、**1つのスクロール可能な設定ペイン**に、折りたためるセクションを縦に並べる。常に先頭の「何を見るか」から始まり、上から順に設定するだけで完成する構成にする。

| 順 | セクション | 含む項目(既存フィールド) | 初期状態 |
|---|---|---|---|
| 1 | **形式** | `chart`(7種をアイコンのみのセグメントで選択、説明文なし)、`title` | 開 |
| 2 | **データ** | `source`(3種のセグメント。意味は `ⓘ` に)、`stage`、期間(プリセット: 7日/30日/90日/全期間/指定。`from_date` / `to_date` は「指定」選択時のみ表示)。`compare_previous` は「詳細」へ | 開 |
| 3 | **軸** | チャート種別ごとの項目(§3.3)。`x` / `y[]` / `series` / `aggregate` / `allocation` / `transform` / `window` / `bins` | 開 |
| 4 | **絞り込み** | `filters` / `filter_join`。**条件はチップ表示**(例: 「キャラクター = ○○」)、クリックで編集、`+ 条件を追加` | 条件があれば開、なければ閉 |
| 5 | **見た目** | `style`(色、凡例、数値ラベルを基本に。軸ラベル、軸の最小/最大、目盛り、並び順は「詳細」へ) | 閉 |
| 6 | **計算式** | `formulas`(行ごと/集計後、列挿入、テンプレート) | 閉 |
| 7 | **詳細** | 既定のままにすることが多い上級項目(`compare_previous`、`allocation`、`window`、軸の最小/最大、目盛り、並び順 等)。**項目はここに集約し、他セクションを軽くする** | 閉 |
| 末尾 | (操作) | 「リセット」「複製」「削除」を**テキストボタンの1行**で。見出し・説明は置かない | 常時 |

- 閉じたセクションの見出しに、**現在値の短い要約**(R6: 約20文字以内)を表示する。
- 現行の「設定上部サマリー」(`#settings-summary`)は**廃止**する。「対象データ数・除外件数」などの状態情報は、設定ペインではなく**プレビュー側(パネルのフッター)に1行**で出す。

### 3.3 チャート種別ごとの表示項目(P2の解消)

| チャート | 「軸」セクションの基本項目(R4: 常設は最大6個。それ以外は「詳細」) | 出さない項目 |
|---|---|---|
| 折れ線 / 棒 | 横軸、縦軸(指標)、系列、集計方法、変換(増加数/増加率/移動平均+`window`)、キャラクター配分 | 列選択、グループ化、`bins` |
| 円 | 分類(`x`)、指標(単一)、集計方法 | 系列、変換、軸の最小/最大 |
| 散布図 | 横軸、縦軸(各1指標)、系列、作品カード表示 | 集計方法、変換 |
| 箱ひげ図 | 分類、指標、系列 | 変換、系列色以外の個別色 |
| ヒストグラム | 指標、`bins`、系列 | 横軸、変換 |
| テーブル | **表示列**、投稿写真の表示、グループ化(項目・順・日付単位・複数値の扱い)、並べ替え(最大5条件・順序変更) | 軸、系列、`bins` |

- 該当しない項目は**非表示**(無効化ではなく)にする。ただしチャート種別を切り替えても、**非表示になった項目の値はそのまま保持**する(切り替えで設定を失わない)。
- 縦軸の指標選択(P3)は、**チェックボックスグリッドを廃止**し、「選択済みチップ + `+ 追加` ドロップダウン」にする(最大6件、`Panel.y` の上限に一致)。チャート種別が単一指標のみの場合は単一選択のドロップダウンにする。

### 3.4 パネルのヘッダーとクイック操作

各パネルのヘッダーに、よく使う変更だけを出す。ダイアログを開かずに操作できること。

- **表示形式の切り替え**(7種、クイックメニュー)
- **期間**の切り替え(プリセット)
- ステージ(作品データのとき)
- 「設定」(右ドックでそのパネルを開く)、「…」メニュー(複製、上へ/下へ、幅、リセット、削除)

## 4. 保存・元に戻す・ロックの統一(P4の解消)

### 4.1 保存モデル

保存の**意味論は現行どおり**(明示保存、`revision` 検証、ロック時は編集不可)。変えるのは**操作の置き場所と表示**。

- 保存操作は**ヘッダー右上の1か所**に集約する。設定ペイン内の「保存」ボタンは廃止(Ctrl/⌘+S は維持)。
- 設定ペイン内の「閉じる」ボタンは廃止。ドックは「×」で閉じるだけで、**変更は失われず、ビューの未保存状態として保持**される。
- 未保存状態は常にヘッダーに表示する:
  - 未保存: 「● 未保存」+ ボタン「保存」「破棄」
  - 保存済み: 「✓ 保存済み」
  - 保存失敗: 短いエラー文(1文)+「再試行」
- 「変更を破棄」は、**最後に保存した状態**へ戻す(確認あり)。保存済みデータは変更しない。
- 「元に戻す」(最大20履歴)は維持。ヘッダー右上のアイコン + `Ctrl/⌘+Z` に配置。「やり直し」(`Ctrl/⌘+Shift+Z`)の追加は任意(P2)。
- 下書きのlocalStorage保持、再読み込み後の復元、別タブ競合ダイアログ(`#conflict-dialog`)、`beforeunload` 確認は**挙動を維持**する。

### 4.2 ロック

- 現行の「鍵ボタン」を、ヘッダーの**状態表示付きトグル**(「編集できます」/「ロック中」)にする。意味・API(`PATCH .../lock`)は変更しない。
- ロック中は設定ドックを**読み取り専用**にする(項目は表示するが操作不可。理由は**ドック上部に1行だけ**: 「ロック中のため編集できません」)。
- 既知の不具合(`hidden` 属性とレスポンシブ指定の競合で未ロック時にロックバッジが見える)を再発させない。`[hidden]` が常に勝つ設計にする。

## 5. リセット機能(P5)

「リセット」は**破壊的操作**になりうる。`AGENTS.md` の「履歴データを黙って削除/書き換えしない」「未保存を失わせない」に従い、次の3段階を実装する。**いずれも作品データ・計測データには一切触れない**(ビュー設定のみが対象)。

### 5.1 パネルを初期値に戻す(P0)

- 場所: パネルの「…」メニュー、設定ペイン末尾。
- 動作: 選択パネルの全フィールドを、**そのパネルの表示形式のテンプレート既定値**(`renderPanelTypes()` の既存テンプレート相当、または `Panel` モデル既定値)に戻す。`id` は維持。
- 確認ダイアログ: 「このパネルを初期値に戻しますか?」(1文。「元に戻す」で取り消せるため補足は不要)
- **下書き変更として扱う**(即保存しない)。「元に戻す」で取り消せる。

### 5.2 ビューを作り直す(P0)

- 場所: ビューの「…」メニュー「テンプレートから作り直す」。
- 動作: 3種類のスターターテンプレート(作品テーブル / キャラクターの勢い / 分析ダッシュボード)から選び、現在のビューの `config.panels` と `layout` をテンプレート内容に置き換える。**ビュー名・id・ロック状態は維持**。
- 下書き変更として扱い、「保存」まで確定しない。元に戻す可能。
- ロック中は無効。

### 5.3 すべてのビュー設定を削除して新規開始(P1)

- 場所: 「MY VIEWS」メニュー末尾の「すべてのビューをリセット…」(目立たない位置、危険色)。
- 要件:
  1. 実行前に、**対象利用者の全ビューをJSONとしてダウンロード**させる(バックアップ。ファイル名例: `analytics-views-backup-<利用者名>-<YYYYMMDD-HHmm>.json`)。ダウンロード操作が行われるまで実行ボタンを有効にしない。
  2. 確認文に、削除されるビュー数と「作品・計測データは削除されません」を明記。**ビュー名の入力、または件数の入力による二重確認**。
  3. 既存API(`DELETE /api/analytics/views/{id}`)を1件ずつ呼ぶ。**ロック中のビューは削除せずスキップ**し、結果に「ロック中のため N 件を残しました」と表示する。
  4. 完了後、スターターテンプレートの選択画面(`#empty-views`)へ。
  5. デモモードは同じ操作をlocalStorageに対して行う。
  6. 他の利用者のビューには触れない。
- **自動実行は禁止**。初回起動時の自動リセットや、マイグレーションでの自動削除は行わない。

## 7. ビジュアルとインタラクション指針

- **ブランド維持**: 主色 `#447869`、インク `#323630`、淡い選択面 `#edf3ef`。トークンは既存の `tokens.css` / `analytics.css` のトークンを再利用・整理し、**新しい色を増やさない**。
- 階層: 1画面に主役を1つ(ダッシュボード = グラフ)。設定は補助。設定ペイン内は**セクション見出し・入力ラベルの2階層まで**(R3)。
- 余白とタップ領域: モバイルは操作要素 **44px 以上**。
- 角丸・影・枠は現行(16pxカード、控えめな影)と整合させ、新規の装飾を足さない。
- **入力方式の方針**: 候補が少ない選択=セグメント/ラジオ、中程度=ドロップダウン、複数選択=チップ+追加、数値範囲=プリセット+詳細入力。長いチェックボックス列は使わない。
- 即時反映: 設定変更はプレビューへ即反映。重いクエリはデバウンスし、読み込み中は前の描画を残して**スケルトン/薄いスピナー**を重ねる(ちらつき防止)。
- 空状態・エラー: データ0件時の案内は**パネル(プレビュー)側**に、短い文+操作ボタン(「全期間にする」「絞り込みを解除」)で維持。検証エラー(422)は**該当項目の直下に1文**で表示する(ペイン上部への重複表示はしない)。
- アクセシビリティ: すべての操作をキーボードで可能に。フォーカスの可視化、`aria-expanded`(セクション)、`aria-live`(保存状態)、ダイアログ以外の設定ペインでは**フォーカストラップを使わない**。ボトムシートは `Esc`/ハンドル操作で閉じられる。コントラストは WCAG AA(本文4.5:1)。`prefers-reduced-motion` を尊重。

## 11. 受け入れ基準(Definition of Done)

1. 設定中にグラフがリアルタイム更新され、設定とプレビューが同時に見える(PC/タブレット/モバイル)。
2. 5タブが廃止され、チャート種別ごとに関連項目のみが表示される。縦軸指標選択のチェックボックスグリッドがない。
3. **§3.0 の原則R1〜R9と数値目標を満たす**(設定ペインの常時表示文字数が現行比で半分以下、常設の説明文・補足文が0個、常設入力項目が6個以下)。実装前後の計測値をPR/報告に記載する。
4. 保存操作がヘッダーに一本化され、未保存/保存済み/失敗が常に分かる。「閉じる」で変更が失われない。
5. パネル単位・ビュー単位のリセットが動作し、いずれも未保存の下書きとして扱われ、元に戻せる。
6. 全ビュー削除は、バックアップDL・二重確認・ロックのスキップを備え、自動実行されない。作品・計測データは変更されない。
7. **既存の保存済みビューが無変更で読み込め、編集・再保存しても情報が欠落しない**。API・DB・集計・収集処理に差分がない(§6.3 を実施した場合のみ、加法的なフィールド追加を除く)。
8. §9 のテストがすべて通る。通らない/実行できないものは理由つきで報告されている。
9. 6サイズでページ横スクロールがなく、キーボードのみで主要フローが完了できる。
10. §10 のドキュメントが更新されている。`.env`・DB・認証情報・個人データがコミットされていない。

| 優先 | 内容 |

## 13. 依頼者に確認が必要な事項(未確定の前提)

実装を止める必要はないが、下記は本書の**仮定**であり、違う場合は修正を依頼する。

1. 「リセット」は §5 の3段階(パネル/ビュー/全ビュー)と解釈した。「現在保存されているビューを全消去して新UIで作り直したい」だけなら、§5.3 を最優先にしてよい。
2. 自動保存は採用していない(現行の明示保存を維持)。自動保存へ変更する場合は、revision競合とロックの扱いを再設計する必要がある。
3. パネル幅・ドラッグ並べ替え(P2)は任意扱い。バックエンド変更を完全に避けたい場合は実施しない。
4. ブランドカラーは維持した。配色も含めて一新したい場合は別途指示が必要。
5. 「情報量が多すぎる」は、説明文・補足文・重複見出し・常時表示される上級項目の多さと解釈した。説明文は `ⓘ` に移し、上級項目は「詳細」に隠す方針(§3.0)。**どの項目を基本に残すかの最終判断は実装時に現行の全項目を棚卸ししたうえで行い、迷う項目は「詳細」へ寄せる**。


## 14. 改訂後の実装記録（2026-10-27）

- §3.0を最優先に、新規パネルの基本は形式・種類・期間・横軸・指標を中心に5〜6項目に絞った。作品は時点、ヒストグラムは区間数、テーブルは列・写真を使用する。名前は常時表示の見出しで確認できるため、入力は「詳細」へ移した。系列・集計・変換・配分なども「詳細」に集約し、§3.3の表は「編集できる項目」の一覧として維持している。
